# Restore Minecraft 1.18 Property Behavior Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore maximum safe Minecraft 1.18 `/properties reload` behavior on Minecraft 26.2 using current settings, permission, gamerule, world-data, and resource-pack APIs.

**Architecture:** Replace obsolete writes into `DedicatedServerProperties` fields with a central settings-update boundary built on `DedicatedServerSettings.update(...)`. Keep each `ServerProperty` responsible for parsing and live side effects. Move 13 formerly supported properties from `unsupported` back to `supported` only after each has a verified 26.2 owner; gamerule-backed keys update world gamerules, permission keys use `LevelBasedPermissionSet`, and resource-pack keys rebuild one `ServerResourcePackInfo` value.

**Tech Stack:** Java 25, Minecraft 26.2 unobfuscated API, Fabric Loader 0.19.3, Fabric API 0.152.1+26.2, Sponge Mixin 0.8.7, Gradle 9.5.0, Fabric Loom 1.17.17.

## Global Constraints

- Preserve command and property names from Minecraft 1.18.
- Prefer public Minecraft 26.2 APIs; add Mixin accessors only for live state with no public setter.
- Never mutate final `Settings.MutableValue` fields with `@Mutable @Accessor`; use `MutableValue.update(registryAccess, value)` through `DedicatedServerSettings.update(...)`.
- A property counts as restored only when clean compile and dedicated-server Mixin startup pass.
- Gamerule replacements persist in world data, not `server.properties`; report this compatibility behavior in migration docs.
- Resource-pack updates must rebuild all components atomically so one changed key does not erase URL, hash, required flag, prompt, or ID.
- Keep keys with no safe runtime equivalent explicitly unsupported.
